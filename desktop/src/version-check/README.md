# 本机构建、更新提示与一键重启

> 草稿，待用户检查。行为依据已确认需求、当前源码与实际客户端验证；更新日期：2026-11-03。

## 功能描述

这个模块把源码编译成可启动的客户端，发布到固定位置，并让正在运行的客户端发现新版本。用户点击“重启并更新”，当前客户端安全收尾后自动退出，再打开同一位置的新版本。

macOS Apple Silicon的固定入口为`desktop/release/mac-arm64/x-scening.app`。每次构建更新这个入口；应用图标和快捷方式继续指向同一位置。客户端每60秒检查一次，通过构建标识核对新产物；每次打包前按AGENTS.md升版。当前功能处理本机已有源码的构建结果，网络下载与远程版本发布由后续功能承接。

## 设计理念

**固定入口贯穿构建和启动。** 用户已明确要求每次构建复用同一个应用。macOS更新时保留`x-scening.app`目录，只整体替换内部`Contents`，让已有图标持续指向这份应用。构建暂存和上一份产物使用`.cache`中的固定内部位置。

**应用完整就绪后再提示。** 一次构建依次完成编译、打包、核对和发布，最后写成功标记。成功标记是一份很小的JSON，记录构建标识、版本与时间；它与应用内的记录一致，客户端才提示更新。完整打包会增加等待时间，换来“看到提示就有可启动的新包”的交付顺序。

**版本号表达发布版本，构建标识区分每次编译。** 每次打包发布前通过`npm version patch --no-git-tag-version`同步更新版本文件与锁文件；Release准备使用minor。重复打包同样更新版本号，构建再生成独立`buildId`。同一批已升版并打包的修改随后提交时沿用本批版本；产物发布后核对源版本、包内版本与成功标记一致。

**点击后完成整个切换。** 用户已明确要求一键退出并自动打开新版本。模块先核对新包，等待现有后台作业结束，再核对一次，随后使用Electron原生重启能力打开固定入口。收尾时间取决于已有任务；等待时显示“正在重启…”，重复请求合并为一次。校验、收尾或安排重启失败时保留当前窗口并展示完整原因，用户可以重试。

需求与实施依据集中在文末的[Spec索引](#spec-索引)。

## 使用方式

前提是桌面依赖与Electron运行环境已经安装，准备方式见[桌面说明](../../README.md)。从项目根目录执行：

```sh
desktop/scripts/run.sh version patch --no-git-tag-version
desktop/scripts/run.sh run build
```

命令结束后显示“本机客户端已就绪”，正式应用位于固定入口。第一次使用从该应用打开；后续构建完成后，运行中的客户端会在下一次60秒检查时显示版本和“重启并更新”按钮，点击即可切换。`desktop/scripts/run.sh run package`执行相同流程；开发预览使用`desktop/scripts/run.sh run start`。

构建失败时查看命令输出，上一份已发布应用和成功标记保留。更新按钮失败时直接查看提示中的完整原因，修复后重试。重开后的采集沿用客户端既有启动行为；当前版本的一键更新使用现有安全退出流程回收自有作业。

已实跑macOS arm64：0.1.12正式窗口实际点击后自动重开，新进程加载下一份构建；0.1.13已完成固定入口打包，并在运行窗口显示更新按钮。详见[一键更新记录](../../../docs/spec/screen-observer-p0/tasks/task-local-client-restart.md)与[0.1.13构建记录](../../../reports/local-client-build-20261103/release-0.1.13/release.md)。Windows、Linux的路径已有代码定义，平台运行步骤待验证。

## 代码说明

覆盖本目录全部7个代码文件。构建入口调用`build.ts`，主进程调用`check.ts`和`restart.ts`，页面使用`LocalBuildNotice.tsx`；路径和数据定义由其余文件统一提供。

### [build.ts](build.ts)：编译并发布完整应用

它先占用构建锁，让同一项目同时执行一个构建。编译完成后，核对主进程包含本轮编号、主进程/预加载/页面产物齐全；再打包到内部暂存区，检查应用归档包含本轮产物。发布时移动上一份内容、放入新内容、最后写成功标记；后续步骤失败会恢复上一份应用。

这种顺序让失败位置和回退对象明确；一次构建会等待编译和打包全部完成。上一份应用只保留一份，长期版本历史由发布流程另行管理。

| 关键函数                                                        | 输入与结果                                             | 关键处理                                                                  |
| --------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------- |
| [`buildLocalClient()`](build.ts)                                | 读取当前项目与package版本，生成构建编号，完成正式发布  | 命令入口；使用已安装的Electron分发打包，完成后打印固定入口                |
| [`publishLocalBuild(root, build, compile, assemble)`](build.ts) | 项目根、构建信息和两个构建步骤；成功后更新固定包与标记 | 校验编译及归档内容；macOS保持应用根目录；标记失败回滚；退出时清理暂存和锁 |
| [`lockBuild(file)`](build.ts)                                   | 锁文件路径，返回独占文件句柄                           | 活动构建保持独占；上次进程已结束时清理遗留锁；锁内容无效时抛错            |
| [`writeMarker(file, build)`](build.ts)                          | 标记路径与构建信息，完成一次写入                       | 先写独占临时文件，再整体替换目标；临时文件收尾清理                        |
| [`runTool(desktop, args, env)`](build.ts)                       | 工作目录、参数和环境，等待子命令完成                   | 输出沿用终端；启动失败或退出码非0时抛错                                   |
| [`isCode(error, code)`](build.ts)                               | 异常及错误码，返回是否匹配                             | 辅助区分文件已存在、路径缺失和进程结束等分支                              |

### [paths.ts](paths.ts)：统一应用位置

`localClientPaths(root, output?)`接收项目根和可选输出根，返回当前平台的应用、可执行文件、归档、包内标记及可替换内容位置。正式输出、内部暂存和回退都调用它，避免分别拼出不同入口。代价是新增平台或产物布局时，需要集中维护这里的映射；macOS以`Contents`作为替换对象。

### [check.ts](check.ts)：确认新包已经就绪

`readLocalBuild(root, running)`接收项目根和当前进程的构建信息，读取成功标记与固定包内标记，核对两者一致、可执行文件和归档存在，再比较构建编号及时间。结果为`current`（当前已生效）、`available`（新构建可用）或`unavailable`（本次检查不可用）。

周期检查只读取小文件和文件状态，完整归档校验由构建入口承担。Electron把ASAR应用归档当作虚拟目录，因此存在性检查接受文件或虚拟目录；读取或校验失败会返回`unavailable`，下轮重新检查。

### [restart.ts](restart.ts)：安全收尾并自动切换

`createLocalClientRestart(root, running, actions)`返回供主进程调用的重启函数。`actions`提供现有安全收尾、原生重启和退出操作；本模块负责把它们按顺序衔接。

返回函数先调用内部`requireUpdate()`确认有新包，再等待`shutdown()`，再次校验后依次调用`relaunch()`和`quit()`。进行中的请求共用同一个承诺，即同一份等待结果；成功后继续复用，失败则清除，允许下一次重试。依赖注入方便用阻塞收尾、坏包及启动异常验证调用顺序；实际进程回收仍归客户端原有服务负责。

### [protocol.ts](protocol.ts)：构建信息与检查状态

`LocalBuildInfoSchema`定义构建编号、三段版本号和生成时间，`LocalBuildStatusSchema`定义三种检查结果。Schema是数据校验规则，构建入口、主进程和预加载共用它们；类型也从这些规则推导。`LOCAL_BUILD_MARKER`统一成功标记位置，`LOCAL_BUILD_CHECK_INTERVAL_MS`规定60秒周期。本文件提供声明，具体读写归构建及检查文件负责。

### [LocalBuildNotice.tsx](LocalBuildNotice.tsx)：更新提示和按钮

`LocalBuildNotice({ bridge })`接收客户端提供的操作接口，订阅后续检查事件，并读取一次初始状态。订阅中先收到新结果时，初始读取返回的较早结果会被跳过；读取不可用时保留最近一次成功显示。

新包可用时显示“新版本 v… 已就绪（当前 v…），重启即可更新。”和“重启并更新”按钮，目标版本取自`latest.version`，当前版本取自`running.version`。点击后禁用按钮、显示等待状态并调用`restartLocalClient()`。异常完整写入页面并恢复按钮。保留最近成功提示可以让临时读取问题平稳恢复；点击时的主进程校验负责确认这一刻仍可切换。

### [notice.css](notice.css)：提示样式

样式随提示组件一起导入，限定更新提示、按钮等待态和错误文本。纸色样式集中在模块内，页面通过组件复用；全局主题调整时仍需核对这里的颜色。它提供样式声明，运行状态由组件控制。
